LyreBirdAudio

RTSP audio streaming for USB microphones, built on MediaMTX and FFmpeg: persistent device names, supervised FFmpeg processes, a monitor that restarts dead streams, a per-stream status report, and diagnostics. Written in Bash.

What is LyreBirdAudio?

LyreBirdAudio publishes USB microphones as RTSP audio streams. It is a set of Bash scripts around MediaMTX and FFmpeg for nodes that run unattended: persistent device names across reboots, a stream manager that starts MediaMTX and one FFmpeg process per microphone and reports which streams are really publishing, a cron monitor that restarts what died, webhook alerts and Prometheus metrics you can wire up, and storage cleanup. It needs no Docker and no language runtime beyond Bash and the standard tools it lists.

It was written to monitor bird activity with USB microphones on spare mini PCs, and suits any setup that needs continuous audio capture from a few USB microphones on a Linux machine.

Key Features

  • Persistent USB device naming via udev
  • Automatic stream recovery & restart
  • Hardware capability detection and device configuration generation
  • Interactive setup wizard (Orchestrator)
  • Systemd service that restarts on failure
  • Cron-based health monitoring
  • Per-stream status document (JSON)
  • Multiplex streaming (amix / amerge)
  • Opus, AAC and MP3 encoding
  • Prometheus metrics export
  • Webhook alerts you trigger yourself (Discord, Slack, ntfy, Pushover, generic)
  • Storage management & retention
  • Git-based version management with history and rollback
  • Durable, atomic writes of configuration files
  • Diagnostics: 25 check groups in full mode
  • RTSP authentication: a local-only-publish mode, or your own MediaMTX settings
  • No Docker, no language runtime beyond Bash

Architecture Overview

At its core, LyreBirdAudio uses FFmpeg to capture audio from ALSA devices and push RTSP streams to MediaMTX, which serves them to any RTSP-compatible client. USB devices are given permanent names through udev rules, so streams keep their names across reboots even when USB enumeration order changes.

Layer Technology Role
Clients VLC, FFplay, OBS, custom Consume RTSP streams
Media Server MediaMTX RTSP serving (the generated configuration disables the other protocols)
Capture FFmpeg + ALSA Audio encoding & publishing
Device Layer udev rules Persistent USB device names
Management Bash scripts + systemd Lifecycle, recovery, monitoring

Get Streaming

  1. Clone the repository 
    git clone https://github.com/tomtom215/LyreBirdAudio.git
cd LyreBirdAudio
chmod +x *.sh
  2. Launch the setup wizard 
    sudo ./lyrebird-orchestrator.sh
# Select: Quick Setup Wizard
  3. Access your streams 
    rtsp://your-server-ip:8554/mic-left

The wizard installs MediaMTX, maps USB devices, starts the streams and runs quick diagnostics. It does not generate the per-device configuration or install the systemd service; the Quick Start guide says how to add both.
