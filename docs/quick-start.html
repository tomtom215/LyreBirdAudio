System Requirements

Operating System

A Linux system with systemd, ALSA and udev; the USB mapper and the stream manager do not run elsewhere. The scripts are written for Debian-family distributions: Ubuntu 20.04 or newer, Debian 11 or newer, and Raspberry Pi OS. That is what the code assumes, not what the project tests. The test suite runs on one Linux system (x86_64, Bash 5.2) with stand-ins for USB hardware and for systemd; it has not been run on a Raspberry Pi, on ARM, on Bash 4.x or on any distribution above, and no test uses real USB audio hardware or a real systemd manager.

Hardware

The installer can fetch MediaMTX builds for x86_64 (amd64), 386, ARM64, ARMv7 and ARMv6. The project has not measured CPU, memory or disk needs: watch lyrebird_mediamtx_memory_bytes and lyrebird_stream_memory_bytes (see Monitoring) on your own hardware before you plan for many streams.

⚠️
USB bandwidth on small boards

A Raspberry Pi shares USB bandwidth between its ports, so the project's advice is one or two microphones per board; for more, use a machine with several USB controllers. The test suite does not measure this.

Software Dependencies

Verify these are installed before proceeding:

# Check required tools
bash --version           # The scripts check for Bash 4.0 or newer
ffmpeg -version          # Audio capture and encoding
jq --version             # Required by the stream manager (start exits 3 without it)
curl --version           # MediaMTX download, API checks
git --version            # Cloning and the version manager
lsusb                    # From usbutils
arecord --version        # From alsa-utils
flock --version          # From util-linux (installed by default on Debian-family systems)

# Install missing dependencies (Ubuntu/Debian)
sudo apt update
sudo apt install -y ffmpeg jq curl git usbutils alsa-utils

Optional:

sudo apt install -y netcat-openbsd  # Only for lyrebird-metrics.sh serve
sudo apt install -y shellcheck bats # Developers only

Clone the Repository

Option A: Main Branch

git clone https://github.com/tomtom215/LyreBirdAudio.git
cd LyreBirdAudio
chmod +x *.sh

Option B: A Tagged Release

git clone https://github.com/tomtom215/LyreBirdAudio.git
cd LyreBirdAudio

# See which tags contain everything that is on main
git tag --contains origin/main

git checkout vX.Y.Z    # a tag from that list
chmod +x *.sh
⚠️
Do not pin a node to a tag that predates the fixes

The newest tag at the time of writing, v1.3.0, was made before the changes these pages describe (the status document, the start policy, the MediaMTX configuration ownership rules, the removal of the watchdog claims, and others). git describe --tags --abbrev=0 returns that tag, and the version manager's "latest stable release" is the same tag, so neither gives you the current code until a newer tag exists. If git tag --contains origin/main prints nothing, no release contains the current code yet: use the main branch.

Run the Setup Wizard

The Orchestrator's wizard walks through four steps:

sudo ./lyrebird-orchestrator.sh

When the menu appears, select 1) Quick Setup Wizard:

  1. Install MediaMTX

    Runs install_mediamtx.sh install: downloads the latest MediaMTX release, verifies its SHA-256 checksum, installs it, and writes /etc/mediamtx/mediamtx.yml and a mediamtx.service unit. If MediaMTX is already installed the wizard carries on.

  2. Map USB audio devices

    Opens the USB mapper in interactive mode, which writes udev rules that give each microphone a fixed name tied to its USB port. Names take effect immediately; no reboot is needed.

  3. Start audio streams

    Runs the stream manager's start and then reads what it left behind: for each stream whether it is publishing, and for each stream that is not, the reason. The summary at the end says whether setup completed, whether only some of the streams are publishing, whether MediaMTX is running and waiting for a microphone, or that setup did not finish, and lists the real stream URLs.

  4. Run quick diagnostics

    Runs lyrebird-diagnostics.sh quick and reports whether it passed, warned or failed.

ℹ️
What the wizard does not do

It does not detect hardware capabilities or generate /etc/mediamtx/audio-devices.conf (that is lyrebird-mic-check.sh -g, or USB Device Management in the menu; without a file every stream uses the defaults), and it does not install the stream manager's systemd unit or the monitor cron job. Run sudo ./lyrebird-stream-manager.sh install afterwards for a node that must come back by itself after a reboot.

Access Your Streams

Each microphone is published under the name you gave it with the USB mapper (the ALSA card id), on RTSP port 8554 unless you changed MEDIAMTX_RTSP_PORT:

rtsp://your-server-ip:8554/mic-left
rtsp://your-server-ip:8554/mic-right
# etc.

./lyrebird-stream-manager.sh status prints the URL of every stream.

Test with common players:

# Test with ffplay (from ffmpeg)
ffplay rtsp://localhost:8554/mic-left

# Test with VLC
vlc rtsp://localhost:8554/mic-left

# Record a stream
ffmpeg -i rtsp://your-ip:8554/mic-left -c copy recording.mkv
⚠️
Anyone who can reach port 8554 can listen and publish

The generated configuration has no RTSP authentication. Use a firewall, and see Security and Configuration for RTSP_AUTH_MODE.

Manual Installation

If you prefer step-by-step control or are automating the setup:

# Step 1: Install MediaMTX
sudo ./install_mediamtx.sh install

# Step 2: Map USB devices (interactive)
sudo ./usb-audio-mapper.sh

# Step 3: Check the names (applied immediately; no reboot needed)
./usb-audio-mapper.sh --list

# Step 4 (optional): Generate the per-device configuration from the hardware
sudo ./lyrebird-mic-check.sh -g

# Step 5: Start streams
sudo ./lyrebird-stream-manager.sh start

# Step 6 (recommended): Install as a systemd service for 24/7 operation
sudo ./lyrebird-stream-manager.sh install
sudo systemctl enable mediamtx-audio
sudo systemctl start mediamtx-audio

Step 5 is safe to repeat: a start on a node where this manager's MediaMTX is already running changes nothing that works. The stream manager's service and the standalone mediamtx.service installed by step 1 conflict with each other; do not enable both (the manager refuses to start, exit 8, while mediamtx.service is active).

⚠️
Install as a Systemd Service for Production

Running the stream manager directly (without systemd) means nothing starts the streams again after a reboot. The service starts them at boot and restarts the manager when it exits; the cron job written by install brings back streams that died.

Verification

Run the built-in health check and look at the stream state:

# Quick health check
sudo ./lyrebird-diagnostics.sh quick

# Stream status: each stream, whether it is publishing, and the overall state
./lyrebird-stream-manager.sh status

The quick check covers:

  • Prerequisites: Bash version, required tools
  • The project's files, versions and log locations
  • USB audio devices detected
  • MediaMTX: binary, configuration file, process, and whether the RTSP port is listening
  • RTSP connectivity, and the entropy pool

status ends with Overall: ok when every expected stream is publishing, and otherwise degraded, failed, waiting_for_devices or stopped (see Monitoring). It exits 0 whatever the state; use status --json when a script has to decide.
