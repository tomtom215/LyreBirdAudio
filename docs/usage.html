Using the Orchestrator

The Orchestrator is a menu-driven interface that runs the individual scripts for you and explains their results. Everything it does can also be done with the scripts directly. 

sudo ./lyrebird-orchestrator.sh

Main Menu

2. MediaMTX Installation & UpdatesInstall, update, reinstall, uninstall, installation status

Managing Streams

The stream manager starts MediaMTX and one FFmpeg wrapper per microphone, and reports whether each stream is publishing. You can use it directly or through the Orchestrator. Every command except status, config and validate needs root.

Stream Manager Commands
start Detect USB devices and start MediaMTX and the streams. Exit 0 when the start policy is met, 9 when not. Safe to repeat
stop Stop the streams and the MediaMTX this manager started
restart Stop, then start (interrupts running streams)
reload Apply a changed MediaMTX configuration without stopping healthy streams
status [--json] Each stream (path ready, bytes flowing, last error) and the overall state; no root needed
monitor One health check; restarts what needs it (cron runs this)
config Show the device configuration file
validate Check the device configuration file
force-stop SIGKILL the processes this manager started and remove its PID files
install Write the systemd unit and the monitor cron job 
# Start all streams
sudo ./lyrebird-stream-manager.sh start

# Check status (no root needed)
./lyrebird-stream-manager.sh status

# Stop all streams
sudo ./lyrebird-stream-manager.sh stop

# Restart after a change to a per-device setting (a running stream keeps the settings it started with)
sudo ./lyrebird-stream-manager.sh restart

# Apply a changed MediaMTX configuration without an outage
sudo ./lyrebird-stream-manager.sh reload

# When a graceful stop fails: kill what this manager started, then start again
sudo ./lyrebird-stream-manager.sh force-stop
sudo ./lyrebird-stream-manager.sh start
ℹ️
What a successful start means

A stream counts as started when MediaMTX reports its path as ready, not when FFmpeg is running. With the default LYREBIRD_START_POLICY=degraded, start exits 0 when at least one stream publishes; with strict it needs all of them; otherwise it exits 9 and stops what it started. With no USB audio device it starts MediaMTX, reports waiting_for_devices and exits 0. Details: Component Reference.

Accessing Streams

Streams are served over RTSP on port 8554 (MEDIAMTX_RTSP_PORT). In individual mode the stream path is the name you gave the microphone with the USB mapper (its ALSA card id); a card with no such name is published under a name derived from the device name.

Stream URLs

# Default pattern
rtsp://your-server-ip:8554/mic-left
rtsp://your-server-ip:8554/mic-right

# status prints the URL of every stream
./lyrebird-stream-manager.sh status

ℹ️
RTSP only

The generated MediaMTX configuration turns WebRTC, HLS, RTMP and SRT off, so there is no browser player or HLS URL. Only RTSP is served. See Configuration.

Multiplex Streaming

Multiplex mode combines all detected USB microphones into one RTSP stream using an FFmpeg audio filter. This is useful for recording all microphones as one feed or for centralized monitoring. The settings of the first device apply to the whole stream, and every microphone that has a capture PCM is included.

amix — Audio Mixing

Mixes all inputs into one stream with the channel count of one input (two stereo microphones give a stereo stream). When FFmpeg's amix has the normalize option (added in FFmpeg 4.4, from its changelog; not checked here) the manager sets normalize=0, so the inputs are summed at full weight: two equal inputs come out about 6 dB louder than FFmpeg's default amix (measured with FFmpeg 6.1.1), and loud inputs can clip. Without the option the manager leaves it out and amix normalizes. It asks FFmpeg which applies; the older-FFmpeg case was tested only with a stand-in whose help text lacks the option, not with FFmpeg 4.2 or 4.3 themselves. 

sudo ./lyrebird-stream-manager.sh -m multiplex -f amix start
# Output: rtsp://host:8554/all_mics

amerge — Channel Merging

Puts the channels of every input side by side: 3 stereo microphones give a 6-channel stream. The codec must be able to encode that many channels. With the default codec, opus, FFmpeg refuses the 4 channels of two stereo microphones; the manager says so and does not start the stream. Use amix, or set CODEC to aac. 

sudo ./lyrebird-stream-manager.sh -m multiplex -f amerge start
# Output: rtsp://host:8554/all_mics

Custom Stream Name

sudo ./lyrebird-stream-manager.sh -m multiplex -n studio start
# Output: rtsp://host:8554/studio

The name is lower-case letters, digits, _ and -, at most 64 characters. Anything else is replaced by _ and the result is logged (Studio Mix becomes studio_mix); a name with no letter or digit, a reserved word (control, stats, api, metrics, health, all, all_others) or more than 64 characters stops the command with exit 4.

Featureamix (Mixing)amerge (Merging)

A microphone that is added while the multiplex stream runs makes the monitor restart the stream, because the wrapper captures only the devices it was started with. When a microphone disappears the wrapper ends, and the monitor restarts it with the remaining ones.

Systemd Service (Recommended for Production)

For 24/7 operation, install the stream manager as a systemd service. Without it, nothing starts the streams again after a reboot. 

# Install and enable the service
sudo ./lyrebird-stream-manager.sh install
sudo systemctl enable mediamtx-audio
sudo systemctl start mediamtx-audio

# Service management
sudo systemctl status mediamtx-audio
sudo systemctl restart mediamtx-audio
sudo systemctl reload mediamtx-audio    # runs "reload": no outage for healthy streams

# Follow the manager's log
sudo tail -f /var/log/lyrebird-stream-manager.log

What install writes:

  • /etc/systemd/system/mediamtx-audio.service, rendered from config/mediamtx-audio.service: Restart=always, a start limit of 10 starts in 20 minutes, ExecReload running reload, and Conflicts=mediamtx.service. There is no watchdog: the unit has no WatchdogSec= and the manager sends no systemd watchdog keep-alives
  • /etc/cron.d/mediamtx-monitor: runs monitor every 5 minutes under flock; an exit status of 2 restarts the service, any other non-zero status is logged with logger. It carries the stream mode, and the unit and the file both carry the ports, bind addresses, RTSP_AUTH_MODE and the other settings you gave install when they differ from the defaults (Configuration)
  • /etc/logrotate.d/mediamtx (when logrotate is installed): rotates the MediaMTX log, the manager log and the FFmpeg logs

The unit writes the manager's output to /var/log/lyrebird-stream-manager.log (StandardOutput=append:), so that file is the log to read; journalctl -u mediamtx-audio shows systemd's own messages about the unit. install must be run from a checkout (it reads the unit template next to the script). To change the stream mode of an installed service, run install again with the -m/-f/-n options; the cron job's mode changes with it. install writes what it is given and the defaults for the rest, so give it the options and the settings (sudo env RTSP_AUTH_MODE=local-only-publish ./lyrebird-stream-manager.sh install) every time.

💡
When Direct Script Execution is OK

Running the script directly (without systemd) is fine for one-time testing, development, debugging, or short manual sessions. For anything running continuously, use the systemd service. The project's tests do not run the service under a real systemd manager; the unit is checked with systemd-analyze verify only.

Health Monitoring

# Quick health check (run daily)
sudo ./lyrebird-diagnostics.sh quick

# Full diagnostics (run weekly)
sudo ./lyrebird-diagnostics.sh full

# One health check of the streams (needs root; this is what cron runs)
sudo ./lyrebird-stream-manager.sh monitor

# Machine-readable state
./lyrebird-stream-manager.sh status --json

# View live logs
sudo tail -f /var/log/lyrebird-stream-manager.log
sudo tail -f /var/lib/mediamtx-ffmpeg/mic-left.log

See the Diagnostics & Monitoring page for full details.
