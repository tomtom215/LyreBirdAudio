Getting Started

Prerequisites

# Development dependencies (Ubuntu/Debian)
sudo apt install -y shellcheck bats shfmt jq curl ffmpeg python3 openssl

The test suite runs on Linux (the project's CI uses the ubuntu-latest runner); macOS is not a tested platform. bashate (a Python package) is the fourth style gate. Package names and versions differ between distributions: CI pins ShellCheck 0.11.0 and shfmt 3.13.1.

Fork and Clone

# 1. Fork on GitHub, then clone your fork
git clone https://github.com/YOUR_USERNAME/LyreBirdAudio.git
cd LyreBirdAudio

# 2. Add upstream remote
git remote add upstream https://github.com/tomtom215/LyreBirdAudio.git

# 3. Make scripts executable
chmod +x *.sh

Verify Development Setup

These are the gates CI runs on every script (a pull request has to pass all of them):

# Syntax check
for script in *.sh; do
    bash -n "$script" && echo "✓ $script"
done

# ShellCheck (warnings and above)
shellcheck --severity=warning --external-sources --shell=bash *.sh

# Formatting
shfmt -d -i 4 -bn -ci *.sh

# Style
bashate --ignore E001,E006,E040,E042,E043 *.sh

# Tests, from the repository root (also fails if a test leaves files in TMPDIR)
tests/check_tmp_leaks.sh

The full suite takes a long time. While you work, run the files for the code you changed (bats tests/test_stream_names.bats) and the whole suite before you push.

Code Standards

Required Header Format

Every script begins with a standard header:

#!/bin/bash
# script-name.sh - Brief Description
# Part of LyreBirdAudio - RTSP Audio Streaming Suite
# https://github.com/tomtom215/LyreBirdAudio
#
# License: Apache 2.0
#
# Version: X.Y.Z
#
# DESCRIPTION:
#   Detailed description of what the script does.
#   Include any important behavioral notes.
#
# USAGE:
#   ./script-name.sh [options] command
#
# DEPENDENCIES:
#   - bash 4.0+
#   - ffmpeg, curl, etc.

set -euo pipefail

The version is a readonly VERSION= (or SCRIPT_VERSION=) assignment; grep -m1 -E '^readonly (SCRIPT_)?VERSION=' *.sh lists them. Change it, and the version table on the Component Reference page, together with the behaviour that needs a new version.

Safety Requirements

  • Always use set -euo pipefail at the top of every script
  • Always quote variables: "${variable}" not $variable
  • Use local for all function-scoped variables
  • Use readonly for constants
  • Validate all inputs at system boundaries (user input, external APIs)
  • Use mktemp for all temporary files
  • Implement signal handlers in scripts that start or change something: trap cleanup EXIT INT TERM

Project Rules

These decisions came out of an audit of the suite; changes are expected to follow them.

  • Configuration is data. Never source or eval a configuration file. Parse it with an allowlist, as the device configuration, storage.conf and alerts.conf are.
  • Find processes by identity, not by name. No pkill/pgrep -f patterns on a normal path. Signal only a PID you recorded, after checking its start time (field 22 of /proc/<pid>/stat) and its executable.
  • Locks never unlink. Use flock on a stable path, open it without truncation, and close the descriptor in every child you spawn.
  • Durable atomic writes go through lyrebird_atomic_write.
  • Ports are configuration. Honour MEDIAMTX_RTSP_PORT, MEDIAMTX_API_PORT and MEDIAMTX_METRICS_PORT everywhere; never hard-code 8554, 9997 or 9998.
  • Do not claim what you have not run. Documentation and help text say only what a command or test showed; say plainly what is not verified.

Style Guidelines

Naming Conventions

Formatting Rules

  • Formatting is enforced by shfmt -d -i 4 -bn -ci: 4 spaces, no tabs, binary operators at the start of a continued line, indented case bodies. Run shfmt -w -i 4 -bn -ci script.sh to fix a file.
  • bashate runs with E001,E006,E040,E042,E043 ignored, so line length is not enforced; keep lines readable
  • Use [[ ]] instead of [ ] for conditionals
  • Use (( )) for arithmetic
  • Add comments for non-obvious logic

Logging Pattern

# Use the shared logging functions (from lyrebird-common.sh);
# the stream manager has its own: log INFO "message"
log_debug "Processing device: ${device_name}"
log_info "Stream started: ${stream_url}"
log_warn "Device busy, retrying in ${delay}s"
log_error "Failed to start MediaMTX: ${error_msg}"

Atomic File Operations

# Replace a file durably: temp file in the same directory, fsync, rename, fsync of the directory
source "${SCRIPT_DIR}/lyrebird-common.sh"
printf '%s\n' "${config_content}" | lyrebird_atomic_write "${config_file}" 0644

For a file that is only a temporary result, mktemp in a directory you own and a trap that removes it is enough.

Testing

Running Tests

# Run all tests (from the repository root)
bats tests/

# What CI runs: the suite, failing if it leaves files in TMPDIR
tests/check_tmp_leaks.sh

# How many tests there are
bats --count tests/

# Run a specific test file
bats tests/test_lyrebird_common.bats

# Run tests matching a pattern
bats --filter "validation" tests/

# Verbose output / TAP format (for CI)
bats --verbose-run tests/
bats --tap tests/

Test Suite Overview

  • One file per script (tests/test_lyrebird_common.bats, test_install_mediamtx.bats, ...) plus files for one area of behaviour (test_stream_*.bats, test_mediamtx_*.bats, test_storage_*.bats, test_lyrebird_updater_*.bats, test_orchestrator_*.bats). tests/README.md lists them.
  • Live tests run against real MediaMTX releases and are skipped unless LYREBIRD_TEST_MEDIAMTX_BINS names the binaries. tests/fetch_mediamtx.sh downloads checksum-pinned 1.15.0, 1.18.0, 1.19.0, 1.21.1, 1.21.2 and 1.21.3 (see the command below). They need curl, ffmpeg, jq, openssl and python3.
  • The suite uses stand-ins for USB hardware, systemctl, sudo and git failures. No test runs on ARM, Bash 4.x or macOS, with real USB audio hardware, or under a real systemd manager (units are checked with systemd-analyze verify).
  • The documentation pages in docs/ are covered too: tests/test_docs_html.bats checks their links and the claims that were once wrong against the scripts' own --help.
LYREBIRD_TEST_MEDIAMTX_BINS="$(tests/fetch_mediamtx.sh)" \
    bats tests/test_mediamtx_live.bats

Writing Tests

Source the real script (every script has a main guard) and call the real functions; do not re-implement a function inside a test and test the copy. Give a test that writes anything a private temporary directory with load scratch_tmpdir. A regression test for a fix should fail on the code before the fix: revert only the fix, run the test, see it fail, restore. End the test name with a tag for what it pins, as the existing tests do ([LB-05], [DOC-02]). 

#!/usr/bin/env bats

load scratch_tmpdir

setup() {
    scratch_setup
    source "${BATS_TEST_DIRNAME}/../lyrebird-common.sh" 2>/dev/null || true
}

teardown() {
    scratch_teardown
}

@test "lyrebird_command_exists returns 0 for bash" {
    run lyrebird_command_exists bash
    [ "$status" -eq 0 ]
}

@test "lyrebird_atomic_write replaces the file and leaves no temp file [example]" {
    printf 'old\n' >"$TEST_SCRATCH/f"
    printf 'new\n' | lyrebird_atomic_write "$TEST_SCRATCH/f" 0644
    [ "$(cat "$TEST_SCRATCH/f")" = "new" ]
    [ "$(ls -A "$TEST_SCRATCH")" = "f" ]
}

Testing Requirements Before PR

  • ☐ All existing tests pass: tests/check_tmp_leaks.sh
  • ☐ New tests added for new functionality, each shown to fail without the change
  • ☐ bash -n script.sh passes (syntax check)
  • ☐ shellcheck --severity=warning script.sh, shfmt -d -i 4 -bn -ci script.sh and bashate pass
  • ☐ Documentation updated: a changed flag, default, exit code or file path is changed in the --help text and on the pages that mention it
  • ☐ Manual testing on a Linux node when the change touches devices, units or MediaMTX; say what you ran and on what, and what you could not run

Contribution Workflow

  1. Create a feature branch 
    git checkout -b feature/your-improvement
# or
git checkout -b fix/issue-description
  2. Make your changes

    Follow the code standards and style guidelines above.

  3. Validate your changes 
    bash -n your-script.sh
shellcheck --severity=warning your-script.sh
shfmt -d -i 4 -bn -ci your-script.sh
tests/check_tmp_leaks.sh
  4. Test on target platforms

    On the platform you changed it for, with actual USB devices where the change touches them. Say in the pull request what you ran it on; the automated tests do not cover real hardware.

  5. Submit a pull request
    • Clear description of changes and motivation
    • Reference any related issues (Closes #123)
    • Include test results
    • Update documentation if needed

Reporting Issues

Found a bug? Please open an issue on GitHub.

Include in Your Report

  1. System info: cat /etc/os-release && uname -a
  2. Script versions: From the Orchestrator menu (Version Management → Show Component Versions) or grep -m1 -E '^readonly (SCRIPT_)?VERSION=' *.sh
  3. Diagnostics: sudo ./lyrebird-diagnostics.sh full > diagnostics.txt 2>&1
  4. Stream state: ./lyrebird-stream-manager.sh status --json
  5. Relevant logs: Last 50 lines showing the error from /var/log/lyrebird-stream-manager.log, and the stream's /var/lib/mediamtx-ffmpeg/<stream>.log
  6. Hardware info: lsusb && ./lyrebird-mic-check.sh

Feature Requests

Feature requests are welcome! Open a GitHub Discussion to discuss before opening a pull request for major features.

Code of Conduct

  • Be respectful and inclusive to all contributors
  • Focus on constructive, actionable feedback
  • Help others learn and grow
  • Keep discussions on-topic and technical
  • Assume good faith from other contributors
