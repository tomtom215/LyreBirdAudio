Audio Device Configuration

Per-device audio settings live in /etc/mediamtx/audio-devices.conf. The stream manager reads it as data: one DEVICE_<NAME>_<SETTING>=value assignment per line, never executed. A line it cannot use is skipped and reported (file, line, key, what was expected), and that setting keeps its default; a bad line never stops a stream from starting.

Auto-Generate Configuration

The lyrebird-mic-check.sh script reads each card's capabilities from /proc/asound and writes the file. The stream manager does not run it for you.

# Generate with normal quality (the default tier)
sudo ./lyrebird-mic-check.sh -g

# High or low quality
sudo ./lyrebird-mic-check.sh -g --quality=high
sudo ./lyrebird-mic-check.sh -g --quality=low

# Without -g it only lists devices and capabilities
./lyrebird-mic-check.sh

An existing file is backed up first as audio-devices.conf.backup.<YYYYmmdd_HHMMSS>; --list-backups and --restore work with those copies.

Manual Configuration Format

<NAME> is the stream's friendly name (the ALSA card id given by the USB mapper, which is also the RTSP path) or the full device name from /dev/snd/by-id, upper-cased, with every other character replaced by _. A value is bare, 'single-quoted' or "double-quoted", and is taken literally: $, backticks and backslashes are not interpreted. No spaces around =; a # comment may follow the value. 

# /etc/mediamtx/audio-devices.conf

# By friendly name (the card id from usb-audio-mapper.sh; this is also the stream path)
DEVICE_MIC_LEFT_SAMPLE_RATE=48000
DEVICE_MIC_LEFT_CHANNELS=2
DEVICE_MIC_LEFT_BITRATE=192k
DEVICE_MIC_LEFT_CODEC=opus

# By full device name (usb-Blue_Microphones_Yeti-00 becomes USB_BLUE_MICROPHONES_YETI_00)
DEVICE_USB_BLUE_MICROPHONES_YETI_00_SAMPLE_RATE=44100
DEVICE_USB_BLUE_MICROPHONES_YETI_00_CHANNELS=1
DEVICE_USB_BLUE_MICROPHONES_YETI_00_THREAD_QUEUE=16384

# A card whose capture device is not PCM 0
DEVICE_MIC_RIGHT_PCM=1
ℹ️
Lookup Priority

For each setting the stream manager uses (1) the friendly-name key, then (2) the full-device-name key, then (3) the built-in default. The built-in defaults come from the DEFAULT_* environment variables below. A DEFAULT_*= line in this file is reported as a problem and ignored.

Validate Configuration

# Check the file with the stream manager's own parser (no root needed; exit 0, or 4 for a bad line)
./lyrebird-stream-manager.sh validate

# Check the settings against what each card reports
sudo ./lyrebird-mic-check.sh -V

# Check the MediaMTX configuration (the flag is in MediaMTX 1.21.1 and later; 1.19.0 and earlier do not have it)
/usr/local/bin/mediamtx --validate-conf=/etc/mediamtx/mediamtx.yml

MediaMTX has no --check flag. Where the installed MediaMTX has --validate-conf, both the installer and the stream manager validate a configuration with it before they replace a file.

Environment Variables

The stream manager reads these when it starts. Defaults are the values in the script. A variable you set in your shell reaches a run you start by hand with sudo env NAME=value ./lyrebird-stream-manager.sh .... It does not reach the service or the monitor:

  • Service: sudo systemctl edit mediamtx-audio and add Environment="NAME=value" lines. A drop-in survives install.
  • Monitor: cron does not inherit the unit's environment. Add NAME=value lines above the job line of /etc/cron.d/mediamtx-monitor. install rewrites that file, so add them again afterwards.
⚠️
Non-default ports must be set in both places

install passes the stream mode on (STREAM_MODE, MULTIPLEX_FILTER_TYPE, MULTIPLEX_STREAM_NAME) but not the port variables: the unit and the cron file it renders carry no port, even when you run install with one set. A monitor that restarts a stream without MEDIAMTX_RTSP_PORT in its environment publishes it to port 8554.

Removed Settings

These settings no longer do anything. If one is present in the environment the manager logs one warning per run and ignores it: HEARTBEAT_INTERVAL, HARDWARE_WATCHDOG_TIMEOUT, ENABLE_HARDWARE_WATCHDOG, HARDWARE_WATCHDOG_DEVICE, LYREBIRD_WATCHDOG_ENABLED, LYREBIRD_WATCHDOG_INTERVAL (there is no software watchdog; for a hardware watchdog use systemd's RuntimeWatchdogSec= or a watchdog daemon), AUDIO_DISK_PERSIST and AUDIO_DISK_PATH (point AUDIO_RECORDING_PATH at persistent storage instead), and LOCK_STALE_THRESHOLD (locks are never stale).

Debugging

Use sudo ./lyrebird-stream-manager.sh -d start for debug output. DEBUG=1 does nothing: the scripts compare DEBUG with the word true, and DEBUG=true in the stream manager also turns on shell tracing (set -x), which is very verbose.

Usage Examples

# Increase the startup delay for a slow USB hub
sudo env STREAM_STARTUP_DELAY=20 ./lyrebird-stream-manager.sh start

# Require every microphone to publish for start to succeed
sudo env LYREBIRD_START_POLICY=strict ./lyrebird-stream-manager.sh start

# Use a different RTSP port for a run you start by hand
sudo env MEDIAMTX_RTSP_PORT=9554 ./lyrebird-stream-manager.sh start

# Install MediaMTX under a custom prefix
sudo env MEDIAMTX_PREFIX=/opt/mediamtx ./install_mediamtx.sh install

MediaMTX Integration

The configuration LyreBirdAudio generates enables RTSP, plus MediaMTX's control API and metrics endpoint on the loopback address, and switches RTMP, HLS, WebRTC, SRT and (on MediaMTX 1.19.0 and later) MoQ off. There is no option that turns the other protocols on. The project's live tests assert, against real MediaMTX 1.15.0, 1.18.0, 1.19.0, 1.21.1, 1.21.2 and 1.21.3 (skipped unless LYREBIRD_TEST_MEDIAMTX_BINS names the binaries), that these are the only sockets MediaMTX opens.

⚠️
RTSP is open by default

With the generated configuration, anyone who can reach port 8554 can read every stream and publish to any path, without a password. The API and metrics refuse callers other than this machine, but there is no authentication on RTSP unless you add it: set RTSP_AUTH_MODE=local-only-publish (below) or write your own MediaMTX authentication, and use a firewall. See Security.

MediaMTX API

The control API is available on this machine for reading state (the default MediaMTX policy refuses other callers):

# List the paths MediaMTX knows
curl http://127.0.0.1:9997/v3/paths/list

# Get one stream; its "available" field says whether it is publishing
curl http://127.0.0.1:9997/v3/paths/get/mic-left

The manager's readiness checks look at the HTTP status and the shape of the answer: a 401 or 403 (an API that wants credentials) never counts against a healthy stream.

Who Owns mediamtx.yml

The first line of a file LyreBirdAudio generated is exactly # Managed by LyreBirdAudio. That line decides who owns the file.

State of /etc/mediamtx/mediamtx.ymlWhat the stream manager does
Missing or emptyWrites it (mode 0644, 0640 when it carries password hashes)
First line is the markerRenders the configuration on every start and reload. An unchanged rendering leaves the file untouched; a changed one is validated, the old file is saved as mediamtx.yml.<UTC stamp>.<nn>.bak, and the new one is written atomically
First line is # MediaMTX Configuration - Audio StreamsThe file an earlier release regenerated on every start. It is adopted: the first start replaces it with the current rendering after a backup, so an edit you made by hand is only in the backup
Any other fileYours. It is validated and used as it is, never written; each start logs one warning. --regenerate-config with start or restart replaces it after saving a backup
  • To keep hand edits in a generated file, delete the marker line. From then on neither the stream manager nor install_mediamtx.sh (without --force) rewrites it.
  • install_mediamtx.sh uses the same generator and the same rule. Its backups are named mediamtx.yml.backup.<YYYYmmdd-HHMMSS> and are not pruned.
  • The old generator's file had its API and metrics on every interface. A node that still has a file an earlier installer wrote (not the stream manager) keeps it, because it has no marker; replace it with sudo ./install_mediamtx.sh --force install, which also reinstalls the latest binary unless you pass -V.
  • RTSP_AUTH_MODE=local-only-publish renders a password-less user restricted to loopback with every permission, plus one read-only user per line of RTSP_USERS_FILE (user:sha256:<base64 of the raw SHA-256 digest>, made with printf '%s' 'the password' | openssl dgst -sha256 -binary | base64). Publishers must connect from loopback, so MEDIAMTX_HOST must stay localhost (or another loopback address). The mode is ignored, with a warning, for a file you own.
  • systemctl reload on the stream manager's unit runs reload, which applies a changed configuration without restarting MediaMTX; some changes (log level, timeouts, RTSP settings, path settings) still make MediaMTX disconnect publishers, and their wrappers reconnect them. The standalone mediamtx.service has no ExecReload: systemctl reload mediamtx does nothing useful, because MediaMTX re-reads its file by itself.

Quality Tiers

The capability checker (lyrebird-mic-check.sh -g --quality=TIER) picks, per card, from what the card reports. Bitrates are the encoder bitrate it writes.

TierSample rateChannelsBitrateBest For
low 44,100 Hz if offered, else 48,000 Hz, else the card's lowest mono if offered 96k mono, 128k stereo (64k and 96k below 44.1 kHz) Speech, monitoring, bandwidth-constrained
normal 48,000 Hz if offered, else 44,100 Hz, else the highest up to 48 kHz stereo if offered 128k mono, 192k stereo (192k and 256k from 96 kHz) General purpose (default)
high 192,000 Hz if offered, else 96,000 Hz, else 48,000 Hz stereo if offered 192k mono, 320k stereo at 192 kHz; 160k / 256k at 96 kHz; 128k / 192k at 48 kHz Music, bird song, archival

Codec Comparison

CodecQuality/BitrateCompatibilityLatency
Opus (default) Best Modern clients, VLC, FFplay. FFmpeg's libopus refuses some channel counts, for example the 4 channels of two merged stereo microphones Very low
AAC Good Widest (iOS, browsers). FFmpeg's aac encoder took 1 to 8 channels and refused 9 when measured Moderate
MP3 Good Universal Moderate

The channel limits above were measured with FFmpeg 6.1.1 and depend on the channel layout. The manager asks the FFmpeg you have, with the exact encoder arguments, before it starts a stream, so a count your FFmpeg refuses is reported instead of failing in a loop.
