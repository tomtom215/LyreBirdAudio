Start Here: Quick Check

Look at the stream state first, then run the diagnostics:

# Which streams are publishing, and why not (no root needed)
./lyrebird-stream-manager.sh status

# Node checks
sudo ./lyrebird-diagnostics.sh quick

status shows, for each stream, whether its path is ready in MediaMTX, whether bytes are flowing, and the last error, then an overall state: ok, degraded, failed, waiting_for_devices or stopped. The diagnostics do not tell you whether a stream is publishing. Their exit code gives the severity of what they found:

Exit CodeMeaning
0All checks passed
1Warnings: system functional but needs attention
2Failures: system degraded or non-functional
127Script error: missing dependencies or permissions

No USB Devices Found

Symptom: the stream manager reports no USB audio devices, or status says waiting_for_devices. By default start then still brings MediaMTX up and exits 0; with LYREBIRD_ALLOW_EMPTY_START=false it exits 6 instead. The monitor starts a stream for each device that appears later. A USB speaker or DAC has no capture device and is skipped on purpose. 

# Step 1: Check what Linux sees
lsusb | grep -i audio
arecord -l

# Step 2: Check ALSA device enumeration
cat /proc/asound/cards

# Step 3: See USB sound cards, their ports and mappings
./usb-audio-mapper.sh --list

# Step 4: Check the mapped names and symlinks
ls -la /dev/sound/by-id/

# Step 5: Re-run device mapping (applies and verifies immediately)
sudo ./usb-audio-mapper.sh
💡
Check Physical Connections

Unplug and re-plug the USB microphone, then check dmesg | tail -20 to see if Linux recognizes the device. Look for "USB Audio" or "snd_usb_audio" in the output.

Streams Won't Start

Symptom: start fails, or completes but a stream is not publishing, or a stream dies right after it starts.

Start with the exit status of start:

ExitMeaningWhat to do
1Not root, MediaMTX did not come up, a port is in use, or something could not be stoppedRead the message and the manager log; sudo ss -tlnp | grep -E '8554|9997|9998'
3A dependency is missing: ffmpeg, jq, arecord, curl or the MediaMTX binaryInstall what the message names (sudo ./install_mediamtx.sh install for MediaMTX)
4Invalid configuration: a bad LYREBIRD_* setting or port variable, an unusable MediaMTX configuration./lyrebird-stream-manager.sh validate, and the message
5Another start, stop or restart holds the lockWait for it. The message names the holder (PID, start time, command). Never delete a lock file
6No USB audio device, with LYREBIRD_ALLOW_EMPTY_START=falsePlug in a microphone, or allow the empty start
8Another MediaMTX owns the node (for example mediamtx.service); nothing was changedsudo systemctl stop mediamtx and disable it if you use the stream manager, or stop the other process
9No stream is publishing (or not every one, under LYREBIRD_START_POLICY=strict); what the start launched was stoppedThe output lists each stream with its reason; see below
 
# Per stream: path ready? bytes flowing? last error?
./lyrebird-stream-manager.sh status --json | jq .

# Check the device configuration file
./lyrebird-stream-manager.sh validate

# Manager log, FFmpeg log of one stream, MediaMTX output
sudo tail -50 /var/log/lyrebird-stream-manager.log
sudo tail -50 /var/lib/mediamtx-ffmpeg/mic-left.log
sudo tail -50 /var/log/mediamtx.out

# Check that MediaMTX answers (the API listens on this machine only)
curl -s http://127.0.0.1:9997/v3/paths/list | head -20

# Check the MediaMTX configuration (MediaMTX 1.21.1 or later)
/usr/local/bin/mediamtx --validate-conf=/etc/mediamtx/mediamtx.yml

# Still stuck: stop what the manager started, then start again
sudo ./lyrebird-stream-manager.sh force-stop
sudo ./lyrebird-stream-manager.sh start

Common causes:

  • The device configuration asks for a sample rate or channel count the card or the codec cannot do: the stream's last_error and the manager log name the setting (for example opus refuses some channel counts; use aac or another count)
  • The device is busy (another process has it open)
  • The card has no capture PCM, or its capture PCM is not number 0 (set DEVICE_<NAME>_PCM)
  • A configuration file of yours that MediaMTX rejects (see Who Owns mediamtx.yml)
# Check if a device is busy
sudo lsof /dev/snd/*

If a lifecycle command was killed and a stack was left running that the manager no longer recognises (Refusing to start: MediaMTX (PID n) is already running ... but was not started by this script), list what force-stop --kill-all would kill, read the list, and only then add --yes: 

sudo ./lyrebird-stream-manager.sh force-stop --kill-all
sudo ./lyrebird-stream-manager.sh force-stop --kill-all --yes

Device Names Change After Reboot

Symptom: a stream's name changes after reboot, or devices swap names.

# Show cards, ports and mappings; flags rules from older versions
./usb-audio-mapper.sh --list

# Check the mapped names and symlinks
cat /proc/asound/cards
ls -la /dev/sound/by-id/

# Re-run the mapper for any card that is not named (applies immediately)
sudo ./usb-audio-mapper.sh -n --card N -f NAME
ℹ️
USB Port Changes

If you physically moved a microphone to a different USB port, re-run sudo ./usb-audio-mapper.sh for it. Names are tied to the physical USB port, not the device itself. Rules written by mapper v1.2.1 and earlier never renamed any device; --list reports them, and re-running the mapper replaces them.

Permission Errors

Symptom: "Permission denied", or the manager exits 1 saying it must run as root.

⚠️
Run as Root or via Sudo

Every stream manager command except status, config and validate needs root, and so do the orchestrator, the installer, the USB mapper (to write rules) and the monitor. The diagnostics and status can run as a regular user for read-only checks, with some results limited: as a regular user status shows a wrapper it cannot identify as Unknown ... run as root rather than "Not running".

# Only if you run arecord or ffmpeg by hand as your own user
sudo usermod -a -G audio $USER
# then log out and back in

Under the systemd unit the state and log directories are created by systemd. If systemctl status mediamtx-audio shows status=226/NAMESPACE, a path in the unit's ReadWritePaths= does not exist. install prefixes a local recording directory with - so that a missing mount (a USB disk that is not there yet) costs the recording, not the streams; any other missing path stops the unit.

MediaMTX Crashes

Symptom: the MediaMTX process dies unexpectedly, streams go offline.

# Check system resources
free -h
df -h

# MediaMTX's own output (both service modes write it here)
sudo tail -100 /var/log/mediamtx.out

# systemd's messages about the unit (the output itself goes to the files above)
sudo journalctl -u mediamtx-audio -n 100
sudo journalctl -u mediamtx -n 100       # only with the standalone unit

# Restart
sudo systemctl restart mediamtx-audio    # stream manager install
sudo systemctl restart mediamtx          # standalone install
  • It exited after you edited mediamtx.yml. A MediaMTX that cannot load a changed configuration file logs the error and exits (with status 0). The unit has Restart=always for that reason, and it will fail again on the same file. Fix the file, or validate it first (MediaMTX 1.21.1 or later: mediamtx --validate-conf=FILE).
  • File descriptors. The units set LimitNOFILE (65536 for the stream manager's service, 65535 for the standalone one); /etc/security/limits.conf does not apply to services. The monitor treats more than 1000 MediaMTX descriptors as critical and has cron restart the service.
  • Reloading. The standalone mediamtx.service has no ExecReload, so systemctl reload mediamtx does nothing useful; MediaMTX re-reads its file by itself. The stream manager's unit has a real reload.

High CPU Usage

Symptom: the system becomes unresponsive, CPU at 100%.

# One monitor pass logs MediaMTX CPU, descriptors and wrapper counts
sudo ./lyrebird-stream-manager.sh monitor

# Which processes are hot (read-only; this signals nothing)
ps -eo pid,pcpu,args --sort=-pcpu | head -10

Solutions:

  • Reduce the sample rate of a device: DEVICE_<NAME>_SAMPLE_RATE=16000 in /etc/mediamtx/audio-devices.conf, then restart
  • Use a lower bitrate: DEVICE_<NAME>_BITRATE=64k
  • Reduce the number of simultaneous streams
  • Look for FFmpeg processes that no wrapper owns (below)
# Stop every stream and MediaMTX the manager started
sudo ./lyrebird-stream-manager.sh stop

# Anything left? This only lists; read it before you add --yes
sudo ./lyrebird-stream-manager.sh force-stop --kill-all

Do not use pkill -f ffmpeg or pkill mediamtx: they kill every such process on the machine, including other recorders, readers and other MediaMTX installations. stop and force-stop signal only processes the manager recorded.

Update Failed

Symptom: lyrebird-updater.sh reports errors, git conflicts, or an update will not complete.

# What the updater knows: version, branch, sync state
./lyrebird-updater.sh --status

# Past updates and rollbacks, and an update that did not finish (local, no network)
./lyrebird-updater.sh --history

# Go back to the version before the last update
./lyrebird-updater.sh --rollback

# Your saved changes, if an update stashed them
git stash list
  • An update that was killed or lost power is found by the next run of the updater, which undoes it (or completes a self-update). Your uncommitted changes are saved in a stash entry named lyrebird-tx-... or lyrebird-recovery-...; they are never discarded.
  • Exit 10: the switch is done, but your changes conflict with the new version; they are in the stash, not re-applied. Exit 11: the automatic rollback could not restore everything; the message names a git checkout --force command. The full list is in the Version Manager reference.
  • Exit 7: another updater is running. Wait for it; never delete the lock file.
  • The menu's "discard all changes and reset" (option 6) is the way to a clean tree; it permanently deletes local modifications.

Debug Procedures

Enable Debug Mode

sudo ./lyrebird-stream-manager.sh -d start

DEBUG=1 does nothing: the scripts compare DEBUG with the word true. In the stream manager DEBUG=true also turns on shell tracing, which is very verbose; the -d option does not.

Test FFmpeg Directly

# Test ALSA capture for a mapped card (here: card id mic-left)
arecord -D hw:CARD=mic-left,DEV=0 -f cd -t wav -d 5 test.wav

# Test FFmpeg capture and publish to a path of its own
ffmpeg -f alsa -i hw:CARD=mic-left,DEV=0 \
  -acodec libopus \
  -b:a 128k \
  -ar 48000 \
  -ac 2 \
  -f rtsp \
  rtsp://localhost:8554/test

Stop the stream manager's stream for that card first: a second open of a busy capture device may fail.

Test RTSP Connectivity

# Check if the RTSP port is listening
ss -tlnp | grep 8554

# Test an RTSP connection
ffplay -i rtsp://localhost:8554/mic-left -loglevel debug 2>&1 | head -50

# Check the MediaMTX API
curl -s http://127.0.0.1:9997/v3/paths/list | python3 -m json.tool

Log Locations

LogPath
MediaMTX output/var/log/mediamtx.out
Stream Manager/var/log/lyrebird-stream-manager.log
Per-stream FFmpeg/var/lib/mediamtx-ffmpeg/<stream>.log (earlier runs: .log.prev.1, ...)
Stream state/run/lyrebird/status.json
Orchestrator/var/log/lyrebird-orchestrator.log
Diagnostics/var/log/lyrebird-diagnostics.log
Alerts/var/log/lyrebird/alerts.log
systemd (the unit's own messages)journalctl -u mediamtx-audio, journalctl -u mediamtx
USB eventsdmesg | grep -i usb

The stream manager's unit appends its output to /var/log/lyrebird-stream-manager.log; the journal holds what systemd says about the unit. The storage script logs to stderr, so its output goes wherever your cron job sends it. 

# Follow the manager and one stream in real time
sudo tail -f /var/log/lyrebird-stream-manager.log /var/lib/mediamtx-ffmpeg/mic-left.log

Collecting Debug Information for Bug Reports

When filing a GitHub issue, please include the following:

# 1. Run full diagnostics (safe to share)
sudo ./lyrebird-diagnostics.sh full > /tmp/diagnostics.txt 2>&1

# 2. The stream state
./lyrebird-stream-manager.sh status --json > /tmp/status.json

# 3. Collect logs (review before sharing — may contain paths)
sudo tar -czf /tmp/lyrebird-logs-$(date +%Y%m%d).tar.gz \
  /var/log/mediamtx.out \
  /var/log/lyrebird-stream-manager.log \
  /var/lib/mediamtx-ffmpeg/*.log \
  /etc/mediamtx/audio-devices.conf \
  /etc/udev/rules.d/99-usb-soundcards.rules 2>/dev/null

# 4. System info
cat /etc/os-release > /tmp/system-info.txt
uname -a >> /tmp/system-info.txt
lsusb >> /tmp/system-info.txt
bash --version >> /tmp/system-info.txt

Include /tmp/diagnostics.txt, /tmp/status.json, the logs tarball, and /tmp/system-info.txt in your GitHub issue. Leave out /etc/mediamtx/mediamtx.yml and rtsp-users.conf: they can contain password hashes.
