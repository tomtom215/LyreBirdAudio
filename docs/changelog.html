Audit remediation (2026-11)

An independent review of revision 5befe80 found defects in the stream manager, the installer, the updater and the documentation, and checking them found more. The IDs in brackets (LB- for the review's findings, X- for those found while checking, DOC- for documentation) are the ones in docs/REMEDIATION-2026-11.md, which also holds the design decisions D1 to D15. docs/remediation-status.json names the tests that cover each item.

Security

  • The MediaMTX API and metrics endpoint listen on 127.0.0.1 by default. In the configuration the stream manager and install_mediamtx.sh generated, they listened on every interface (ports 9997 and 9998). MEDIAMTX_API_BIND and MEDIAMTX_METRICS_BIND change the address; an empty value means every interface. MediaMTX's own default rules already refused API and metrics calls from other machines, so a working setup is not affected. [LB-06, LB-22]
  • Only RTSP is open to the network. SRT, RTMP, HLS and WebRTC are off in every generated configuration, MoQ is off on MediaMTX 1.19.0 and later, and no setting turns any of them on. The installer's old configuration left SRT listening, and MoQ on 1.19.0 and later. With the generated configuration MediaMTX opens RTSP (every interface), the API and metrics (loopback) and the two UDP ports RTSP uses (8000 and 8001 by default), and nothing else; checked on MediaMTX 1.15.0, 1.18.0, 1.19.0, 1.21.1, 1.21.2 and 1.21.3. [LB-06]
  • RTSP is still open by default: anyone who can reach port 8554 can publish to and read every stream, as before. The new RTSP_AUTH_MODE=local-only-publish closes it without editing the file: this machine needs no password, and every other client must be a user listed in RTSP_USERS_FILE and can only read. Publishers must then connect through a loopback name (MEDIAMTX_HOST of localhost, 127.x or ::1; the manager warns otherwise). lyrebird-stream-manager.sh help shows the file format; docs/SECURITY-GUIDE.md covers authentication. [LB-06]
  • A cron restart no longer loses the authentication mode or the ports. lyrebird-stream-manager.sh install wrote only the stream mode into the unit and the cron file, and the monitor that cron runs brings a MediaMTX that has died back by rendering mediamtx.yml again, from the defaults. With RTSP_AUTH_MODE=local-only-publish the file then had no authInternalUsers and anonymous remote publishing worked again (seen after kill -9 of MediaMTX); a node with its own ports and bind addresses was put back on 8554, 9997, 9998 and 127.0.0.1. install now writes the nine settings that decide this into both files, and the updater's service reinstall keeps them (see "The unit and the cron monitor" below). A node installed before this release has none of them in its files: see "Upgrading an existing node". [X-58, X-52]
  • A mediamtx.yml you edited is no longer overwritten. The manager regenerated the file on every start, so a password, bind address or file mode you set was lost. Only a file whose first line is # Managed by LyreBirdAudio is rewritten (after a backup); any other file is yours, is used as it is and is never written. [LB-22]
  • The device configuration is read as data and never run. /etc/mediamtx/audio-devices.conf was loaded with source, so a line such as exit 0 ended the manager and a $(...) ran as root. [LB-08, X-09]
  • Generated files cannot be injected. Every value in a generated stream wrapper is quoted (a ", $(...), backtick or trailing backslash in a setting used to run or break the wrapper), and a stream name can no longer add a YAML key (runOnInit ran as a command), a systemd directive or a cron line. [LB-09, X-10, X-11, LB-04]
  • install_mediamtx.sh update always checks the checksum. It used to run MediaMTX's own --upgrade, which downloads the newest tag and replaces the binary without any checksum check. [X-41]
  • The metrics HTTP server listens on 127.0.0.1 by default. It listened on every interface while its log said "localhost". It still has no authentication or TLS. [X-17]
  • docs/SECURITY-GUIDE.md Option 2 set the admin password to a literal string. MediaMTX does not expand ${MEDIAMTX_ADMIN_PASSWORD} in its YAML, so the password was that text (checked on MediaMTX 1.21.1: 200 for the literal string, 401 for the real value). If you followed that guide, change the password. [DOC-01]

Changed behaviour

Start, stop and ownership

  • start reports what happened. Exit status 0 means the start policy is met, and 9 (new) that it is not. LYREBIRD_START_POLICY=degraded (the default) requires one stream to be publishing, strict requires the stream of every detected device; "publishing" is what MediaMTX's API reports, not that FFmpeg is running. Before, start printed [FAIL] lines and still exited 0. A failed start stops what that run started and leaves a stack that was already running alone. Under systemd, a node whose microphones all fail now has a failed start, which Restart=always retries. [LB-03]
  • start is safe to repeat. With the manager's own MediaMTX running it changes nothing that works (same process IDs, no outage, configuration not rewritten) and starts only a stream whose wrapper is missing. Before, every start cleaned up and restarted everything. [LB-01]
  • One MediaMTX owner. mediamtx-audio.service now conflicts with mediamtx.service (Conflicts=), and start, restart and reload refuse with exit 8 (new) and change nothing while mediamtx.service is active or a MediaMTX the manager did not start is running on its configuration. The old sample unit made the manager depend on mediamtx.service while the manager started its own MediaMTX on the same file and port. [LB-02]
  • No USB microphone is not a failed start. start starts MediaMTX, reports waiting_for_devices and exits 0; it used to exit 6 without starting anything. LYREBIRD_ALLOW_EMPTY_START=false restores exit 6. The wait for USB devices to settle no longer counts an empty list as settled. The monitor starts the stream of each device that appears, restarts a multiplex stream when a device is added, and restarts a MediaMTX that is gone while the node is meant to run (start was run and stop was not, which the manager records in /run/lyrebird/desired-running), within CRON_RESTART_MAX_PER_HOUR. [LB-07, X-03]
  • Lifecycle commands never overlap, and no lock goes stale. Locks are flocks on files that are never deleted or truncated; the kernel releases one when its holder dies, so LOCK_STALE_THRESHOLD is gone. stop and force-stop now refuse with exit 5 (nothing changed) when another lifecycle command still holds the lock after STOP_LOCK_TIMEOUT seconds (default 5); the monitor skips its cycle, exit 0, while one runs. The "Failed to acquire lock" message names the holder: do not delete lock files by hand. MediaMTX, the wrappers and FFmpeg no longer inherit the lock. [LB-05, X-02]
  • Processes are found by identity, never by name. The manager signals only processes recorded in its own PID files (checked against the process start time, which is kept in a <pid file>.id record beside each) that are what it started. stop no longer kills other FFmpeg processes that read a stream, and force-stop kills only what this manager started. force-stop --kill-all prints what it would kill and exits 1; force-stop --kill-all --yes kills it: the only broad kill. The first signal is SIGTERM, then SIGKILL after the timeout. stop exits 1 when something could not be stopped. The installer stops MediaMTX through its owner (systemd or the manager) and, as a last resort, by executable path and configuration file; its status no longer reports another installation's MediaMTX as "Running (manual)". [LB-10]

Health checks and monitoring

  • Silence is measured on the published stream. The monitor reads each published stream over RTSP for 3 seconds (AUDIO_LEVEL_SAMPLE_DURATION) at most every 240 seconds (AUDIO_LEVEL_CHECK_INTERVAL) and logs DEAD MIC once per silence episode, after 60 seconds (AUDIO_SILENCE_WARN_DURATION) at or below -60 dB (AUDIO_SILENCE_THRESHOLD_DB). AUDIO_LEVEL_CHECK_ENABLED=true was already the default, but nothing ever ran it. It does not open the sound card. It adds at most one short RTSP read session per stream and monitor run (visible in MediaMTX's log and API). There is no metric or alert for it: the log line is the signal. [LB-14, X-05]
  • The heartbeat says only what it is. /run/mediamtx-audio.heartbeat holds the time of the last monitor run. lyrebird_heartbeat_healthy is 1 when the monitor ran within LYREBIRD_HEARTBEAT_MAX_AGE seconds (default 900); it was tied to 60 seconds although the monitor runs every 5 minutes. It proves that the monitor ran, not that any stream is up. [LB-15, X-13]
  • MediaMTX readiness is checked, not assumed. Readiness, the API version and the per-stream probe check the HTTP status and the shape of the answer; any answer used to count. A 401 or 403 (an authenticated API) or an API that does not answer is "unknown" and never counts as a failed stream: before, such a stream was restarted after three monitor runs in a row. [LB-13]

Configuration

  • mediamtx.yml has an owner. A file with the # Managed by LyreBirdAudio first line is rewritten only when its content changes, after a backup mediamtx.yml.<UTC time>.<nn>.bak (the newest MEDIAMTX_CONFIG_BACKUPS, default 5, are kept), written so that a power cut leaves the old or the new file. The manager and the installer render it with one generator. A file without the line is yours: --regenerate-config start (or restart) takes it over after a backup; to keep hand edits in a managed file, delete the first line. Where MediaMTX has --validate-conf (1.21.1 and later), the new file is checked by the binary before it replaces the old one. The file is written after the port check, not before. [LB-22, LB-23]
  • The file an earlier manager wrote is adopted. A mediamtx.yml whose first line is # MediaMTX Configuration - Audio Streams is replaced by the current rendering at the first start or reload (after a backup), with a log line saying so. An edit you made to it by hand is in the backup only. The file the earlier installer wrote (first line a row of #) is not adopted: it is yours, and every start warns about it. [X-38]
  • The device configuration is checked, not trusted. The file is read line by line against a list of keys: DEVICE_<NAME>_<SETTING>=value, <SETTING> one of SAMPLE_RATE, CHANNELS, CODEC, BITRATE, THREAD_QUEUE and PCM, with the values each accepts. A line that cannot be used is skipped, logged with its file, line and key, and its setting keeps the default; it no longer stops start (which exited 4 for a syntax error). The new lyrebird-stream-manager.sh validate checks the file (exit 4 when a line cannot be used). Keys in mixed case, which lyrebird-mic-check.sh used to write and which were ignored, are now read and so apply. Settings are no longer taken from DEVICE_* environment variables. DEFAULT_*= lines in the file are an error (set them in the environment). BITRATE must be NNNk (128000 is an error); CODEC must be opus, aac or mp3 (pcm_s16le was accepted and left local recording empty). [LB-08, X-09, X-28]
  • Stream names are canonical. One rule serves the MediaMTX path, the publisher URL, PID file, status and systemd line: lower case, [a-z0-9_-], first character a letter or digit, at most 64 characters; other characters become _ (Studio Mix is studio_mix, My-Mix_2 is my-mix_2). The -n name goes through the same rule, and the result is logged when it differs. A name that is reserved (control, stats, api, metrics, health, all, all_others), too long or without a letter or digit ends the command with exit 4. A name with a space made MediaMTX refuse to start. [LB-04]
  • The three ports are honoured everywhere. MEDIAMTX_RTSP_PORT, MEDIAMTX_API_PORT and MEDIAMTX_METRICS_PORT reach the generated file, readiness and stream probes, the port check, the wrappers' publish URL and every URL the manager prints; the manager hard-coded 8554 and 9997 before. A value that is not an integer from 1 to 65535 ends every command with exit 4. install writes them into the unit and the cron file when they are not the defaults. The port check no longer counts a client socket that merely uses the number. [X-19, X-58]
  • The capture device is not assumed to be PCM 0. The manager lists a card's capture PCMs; DEVICE_<NAME>_PCM picks one if there are several. [LB-24]
  • Multiplex mode asks FFmpeg before it starts. The amix normalize option needs FFmpeg 4.4; on 4.2 and 4.3 (Ubuntu 20.04, Debian 11) the stream used to fail with "Option not found" and now starts without it, which gives amix's default scaling. From 4.4 the mix stays the plain sum (normalize=0), 6 dB louder than amix's default for two equal inputs. A channel count the codec cannot encode (for example two stereo microphones with amerge and opus, 4 channels, on FFmpeg 6.1.1) is refused before the wrapper is written, with the alternatives in the message; an individual stream's CHANNELS is checked the same way. [X-20, X-49]
  • Recording is RAM-only unless you point it elsewhere. With AUDIO_LOCAL_RECORDING=true the segments go to AUDIO_RECORDING_PATH (default /dev/shm/lyrebird-buffer, lost at reboot or power loss): the last AUDIO_RECORDING_SEGMENTS x AUDIO_RECORDING_SEGMENT_TIME seconds (one hour by default) per stream, overwritten in place. For recordings that survive, set AUDIO_RECORDING_PATH to persistent storage. After a wrapper restart the segments are not in slot order: sort them by modification time. [LB-16]
  • Two log variables. STREAM_MANAGER_LOG_FILE is the manager's own log (default /var/log/lyrebird-stream-manager.log); MEDIAMTX_LOG_FILE is only where MediaMTX's output goes (default /var/log/mediamtx.out). They used to be one variable. [X-15]
  • FFmpeg logs are kept. A new wrapper moves the previous <stream>.log to <stream>.log.prev.1 and shifts older ones up; FFMPEG_LOG_KEEP (default 3, at most 20) bounds them. start, stop and force-stop no longer delete logs. [X-25]
  • One directory for the FFmpeg logs, and each log rotated once. The manager writes them to /var/lib/mediamtx-ffmpeg/<stream>.log (MEDIAMTX_FFMPEG_DIR). The diagnostics' FFmpeg log directory and the orchestrator's "View Stream Logs (FFmpeg)" looked in /var/log/lyrebird and now default to that directory (FFMPEG_LOG_DIR still overrides them; the manager never read it). config/lyrebird-logrotate.conf and the file install writes, /etc/logrotate.d/mediamtx, both listed the MediaMTX and the manager log, and logrotate refuses a log that two files list (checked with logrotate 3.21.0: duplicate log entry, and the log was not rotated). install owns MEDIAMTX_LOG_FILE, STREAM_MANAGER_LOG_FILE and the FFmpeg logs; the shipped file now covers only /var/log/lyrebird/*.log and the orchestrator, updater, diagnostics and USB mapper logs. [X-51]
  • reload is a real command. lyrebird-stream-manager.sh reload re-renders the MediaMTX configuration and lets the running MediaMTX apply it; the manager stops nothing. Changes to the log level, timeouts, metrics, RTSP settings or a path's settings make MediaMTX disconnect that stream's publishers, which reconnect (a gap); the command says which keys do. Per-device audio settings are applied by restart, not reload. Exit 7 means MediaMTX is not running. A terminal hang-up (SIGHUP) of a manually started manager now runs reload; it used to stop every stream. [LB-11, X-46]

systemd units

  • One unit template, rendered at install. config/mediamtx-audio.service is the template; lyrebird-stream-manager.sh install renders it and the monitor cron file before it writes anything, and refuses (exit 4, nothing written) a value a unit cannot carry. install must be run from a checkout (it needs config/ next to the script). Compared with the unit install used to write: Restart=always (was on-failure), the start limit is 10 in 20 minutes in [Unit] (StartLimitInterval= sat in [Service]), ExecReload runs the real reload (was restart), ProtectSystem=strict with every path the manager writes made writable (was full), start and stop timeouts computed from the manager's own timings (560 s and 130 s for 8 streams; were 300 and 120), Conflicts=mediamtx.service, no Group=audio and no faked INVOCATION_ID. The unit has no WatchdogSec=: the manager sends no keep-alives. A node keeps its old unit until install runs again (the updater does that). [LB-11, LB-12, X-12]
  • The standalone MediaMTX unit (config/mediamtx.service) conflicts with the manager's unit and has the start limit in [Unit], and install_mediamtx.sh renders the unit from that file. Compared with the unit the installer wrote: 5 starts in 300 s (was 3 in 60 s), RestartSec=5 (was 10), no ExecReload, MemoryMax=512M. systemctl reload mediamtx now says the unit cannot reload: MediaMTX re-reads a changed configuration file by itself (checked on 1.15.0 and 1.21.1), and SIGHUP ends it. A node keeps its unit until install_mediamtx.sh --force install. [LB-02, X-12, LB-12]
  • The unit and the cron monitor get the node's mode and settings. install writes STREAM_MODE, MULTIPLEX_FILTER_TYPE and MULTIPLEX_STREAM_NAME into /etc/cron.d/mediamtx-monitor; before, the monitor of a multiplex node ran in individual mode and started per-device streams next to the multiplexed one. It also writes, as Environment= lines in the unit and as NAME=value lines in the cron file, the settings that decide where MediaMTX listens and who may connect, when they are set and differ from their defaults: MEDIAMTX_RTSP_PORT, MEDIAMTX_API_PORT, MEDIAMTX_METRICS_PORT, MEDIAMTX_API_BIND, MEDIAMTX_METRICS_BIND, RTSP_AUTH_MODE, RTSP_USERS_FILE, MEDIAMTX_HOST and MEDIAMTX_BINARY. A value the files cannot carry stops install with exit 4 before anything is written; with none of them set the two files are what they were. install writes what it is given and the defaults for the rest, so give it the options and settings every time you run it. Not carried: the path variables and the audio settings. [X-32, X-58]

Installer (install_mediamtx.sh 2.1.0)

  • The configuration is the shared generator's: first line # Managed by LyreBirdAudio, API and metrics on 127.0.0.1, everything but RTSP off, and a catch-all path so publishers are accepted (the old file's paths: {} made MediaMTX answer every publisher with "path is not configured"). It is generated for the version of the binary that will run it. An existing marked file is replaced only if its content changes, after mediamtx.yml.backup.<time>; a file without the marker is left alone unless --force, which saves a backup first. Exit 9: MediaMTX rejected the generated file (1.21.1 and later); nothing is written. [LB-06, LB-22]
  • Exit 11 is the binary steps. An archive that does not extract or holds no binary, and a copy or an atomic move into place that fails, exit 11 (install and update). They exited 7, which also means "already installed", "not installed" and "could not stop MediaMTX", so the wizard of the orchestrator, which carries on after 7, carried on after a failed install. 7 still ends an update that was rolled back because the new binary does not run or the service did not come back. --help lists the codes 0 to 11. [X-57]
  • Ports are validated before anything is downloaded or written: a MEDIAMTX_*_PORT that is not an integer from 1 to 65535, or two equal ones, ends install with exit 10 and names the variable. [X-43]
  • install needs lyrebird-common.sh next to the installer (exit 4 otherwise); --no-config --no-service does not. [LB-22]
  • update downloads and verifies first, then stops MediaMTX, so a failed download or a checksum mismatch (always fatal, even with --force) leaves MediaMTX running. It installs atomically, checks that the new binary runs, and rolls back to the previous one when it does not run or the service does not come back. A MediaMTX started by hand is stopped, not started again; the command to start it is printed and the exit status is 0 (it used to end rolled back with exit 7). Across MediaMTX 1.19 an update adds moq: no to a generated configuration; before, MoQ listened on every interface. update still never rewrites the configuration or the unit otherwise. [X-39, X-40, X-41, X-42]

Updater (lyrebird-updater.sh 1.8.0)

  • --history and --rollback [VERSION] exist (the README described them before they existed). --history lists updates, rollbacks and resets from a local log (<git-dir>/lyrebird-updater/history.log), and any update that did not finish. --rollback returns to the version the last update came from, or to a release tag or commit already in the clone; neither needs the network. [X-21]
  • An update is a journalled transaction. An update killed halfway (a power cut, SIGKILL) is undone by the next run: back to the recorded commit, stash and service restored. Declining "Save your changes temporarily?" or a failing stash no longer discards your uncommitted edits; a conflicting stash restore leaves a clean tree, keeps your changes in the stash and exits 10. File modes survive (every tracked *.sh stays executable), and no command waits on an unreachable remote: a fetch is bounded (30 seconds, 3 attempts). [X-21]
  • The lock is a kernel flock on <git-dir>/lyrebird-updater/updater.lock, never deleted; it is no longer an untracked directory in the working tree. flock (util-linux) is now a prerequisite (exit 2 without it). Migrations now also run after a self-update. [X-31]
  • A service reinstall keeps the node as it is. When the manager script changed, the updater runs install again. It ran it with no options, which put the cron file of a multiplex node back to individual mode. It now gives install the stream mode, filter and name and the nine settings above as the installed unit sets them (the cron file's value for one the unit does not set), so the unit and the cron file keep the node's mode, ports and authentication. Environment= lines you added are kept, as before. [X-52, X-58]
  • Exit codes: 6 (the version is not in the clone), 10 (switched, but your saved changes conflict and are in the stash), 11 (the automatic rollback could not restore everything), 12 (input ended at a menu prompt). A switch that fails in the menu is reported and the menu stays open; Q leaves with the status of the last switch. [X-21, X-31]

Orchestrator (lyrebird-orchestrator.sh 2.2.0)

  • It says what a start really did. Audio Streaming Control (menu 4: Start All Streams, Restart All Streams) and the Quick Setup Wizard read /run/lyrebird/status.json (or status --json) and print each stream's state and reason, then the next step; the wizard's final message is decided by the start it just ran (it used to report success after a failed start, and warnings after a good one). Exit codes of the stream manager and the updater are explained in words. The wizard no longer advises a reboot. Version Management (menu 6) has 3) Show Update History and 4) Roll Back to a Previous Version. Listing stream URLs no longer ends the orchestrator on a system without the ip command. [LB-21, X-21]
  • It finds MediaMTX and the streams by identity. The menu header's MediaMTX: line is the program at MEDIAMTX_BINARY running the manager's configuration file, not any process called mediamtx, and Active Streams: counts the manager's wrapper processes, not every ffmpeg on the host. The orchestrator no longer needs pgrep. The diagnostics find MediaMTX the same way. The two lookups are lyrebird_mediamtx_pids and lyrebird_stream_wrapper_pids in lyrebird-common.sh 1.2.0. [X-54]
  • It follows the manager's port. "View Stream URLs" prints MEDIAMTX_RTSP_PORT (it printed 8554), and the diagnostics read MEDIAMTX_RTSP_PORT too, with MEDIAMTX_PORT only as the fallback. [X-55]
  • It explains installer exit 11 as a failed binary installation, and no longer says that exit 7 can mean a failed install step. [X-57]

Metrics (lyrebird-metrics.sh 1.4.0)

  • serve and its options exist as documented: serve [--port PORT] [--bind ADDR] (and --serve [PORT]). It answers GET / and GET /metrics with correct HTTP framing, one connection at a time, a document generated after the request arrived, and no longer loops while the port is taken (exit 2 after 5 attempts). --file replaces the file atomically and keeps the previous one when anything fails. [LB-18, X-17]
  • Exit status is no longer always 0: 2 when nothing could be delivered, 3 when a collector failed. New lyrebird_scrape_success and lyrebird_collector_success{collector} say which; a source that cannot be read makes its metrics absent, not 0 (alert on lyrebird_scrape_success == 0). [LB-18]
  • MediaMTX is this installation's MediaMTX: the configured binary on the configured configuration (MEDIAMTX_BINARY, MEDIAMTX_CONFIG_FILE), as for the manager; a process whose command line merely contains "mediamtx" no longer counts. Liveness is read from /proc, not kill -0. Run the exporter as root: as another user MediaMTX details are left out and the scrape counts as degraded (exit 3). One scrape spends at most LYREBIRD_API_TIMEOUT seconds (default 5) on the MediaMTX API; a refused API costs 20 ms, not 1 second. [X-30]
  • The exporter follows the manager's FFmpeg directory. It reads MEDIAMTX_FFMPEG_DIR, the manager's variable, and FFMPEG_PID_DIR only as the fallback; before, a node that moved the directory with MEDIAMTX_FFMPEG_DIR showed no streams unless FFMPEG_PID_DIR was set too. [X-55]

Storage (lyrebird-storage.sh 1.3.0)

  • The documented cron lines work. cleanup --quiet and monitor --once are implemented (monitor checks once and exits; there is no --interval and never was). /etc/lyrebird/storage.conf is read, as data, when it exists, and not at all when anyone can write it or another user owns it (reported, exit 4); an /etc/lyrebird/storage.conf written from the old documentation takes effect with this version. Exit status 3 also covers a directory that could not be listed, and 4 means lines of the configuration file were ignored. [DOC-05, X-29]
  • Retention and emergency cleanup see every recording. .aac was missing from the list, so CODEC=aac recordings were never cleaned (the list is now opus ogg aac adts m4a mp3 flac wav). Empty segments left by a killed FFmpeg are removed once idle for LYREBIRD_ACTIVE_SEGMENT_SECONDS (default 900); a file written more recently is never evicted. Emergency cleanup removes at most 100 of each kind per run, oldest first, and no longer deletes the buffer's stream directories (FFmpeg lost its recording leg until restarted). Symlinked configured directories are followed. [X-14, X-29]

Alerts (lyrebird-alerts.sh 1.1.0)

  • Delivery is tracked per destination. An identical alert is not sent again to a destination that confirmed it within LYREBIRD_ALERT_RATE_LIMIT seconds (default 300); a destination that failed is retried by the next identical alert. Five parallel identical alerts deliver once per destination. New exit status 5: some destinations have the alert and at least one failed (0 now means every destination that needed it has it). A script that sources the library and calls send_alert under set -e must handle 3, 4 and 5. [LB-17]

Test suite and CI (for contributors)

  • The suite no longer writes the machine's real /var/log, /etc or /run, and LYREBIRD_LEAK_CHECK_HOST=1 tests/check_tmp_leaks.sh fails a run that does (CI sets it). Tests that tested copies of functions defined in the test file were converted to run the real script, or removed where a real test already covered the behaviour. [X-35, X-18]
  • CI runs on every pull request and push to main, with no path filter. The CI Summary job fails unless every job succeeded, shfmt and bashate block, every Action is pinned to a commit and every downloaded tool is checked against a hash. The live matrix covers MediaMTX 1.15.0, 1.18.0, 1.19.0, 1.21.1, 1.21.2 and 1.21.3, plus an advisory canary on the newest upstream release. A tag runs the whole pipeline before a release is published, with a source tarball and SHA256SUMS; publishing can be repeated. [LB-19, LB-20, X-22, X-16]
  • The live steps run tests/test_stream_names.bats and tests/test_docs_security.bats too, once per pinned MediaMTX version and in the canary. The four live tests of the first (the stream-name matrix, runOnInit injection, quoted keys and all_others) had never run against a real MediaMTX in CI; the second loads every YAML block of the security guide into each binary that has --validate-conf. [X-60]

Upgrading an existing node

Which command refreshes which file:

  • The scripts of the checkout: sudo ./lyrebird-updater.sh.
  • /etc/systemd/system/mediamtx-audio.service, /etc/cron.d/mediamtx-monitor and /etc/logrotate.d/mediamtx: sudo ./lyrebird-stream-manager.sh install. The updater runs it when the manager script changed and the service is installed. A node installed before this release carries none of the nine settings install now writes: run install once with the ones the node uses (step 6).
  • /etc/mediamtx/mediamtx.yml of a manager node: the first start, if an earlier manager wrote it; otherwise sudo ./lyrebird-stream-manager.sh --regenerate-config restart.
  • /etc/mediamtx/mediamtx.yml and /etc/systemd/system/mediamtx.service of a standalone MediaMTX: sudo ./install_mediamtx.sh --force install, which reinstalls the latest binary too (-V vX.Y.Z pins one).
  • The MediaMTX binary: sudo ./install_mediamtx.sh update, which touches nothing else.
  • /etc/mediamtx/audio-devices.conf: never rewritten; sudo ./lyrebird-stream-manager.sh validate checks it.

In this order:

  1. Look at what runs: systemctl is-active mediamtx mediamtx-audio. If both are active, choose one: the manager's unit conflicts with mediamtx.service, and the manager refuses to start (exit 8) while mediamtx.service is active. A node that streams microphones uses mediamtx-audio.service; the standalone unit is for a MediaMTX-only node.
  2. Update the checkout with sudo ./lyrebird-updater.sh (option 1, or 3 for a tag) to the release that contains this section; v1.3.0 does not. When mediamtx-audio.service is installed and the manager script changed, the updater stops the service, runs install (keeping the Environment= lines you added to the unit and the mode and settings the unit or the cron file already carries), reloads systemd and starts the service. Without the updater, run sudo ./lyrebird-stream-manager.sh install with the -m, -f and -n options you used before (it rewrites the unit, so keep local settings in systemctl edit mediamtx-audio), then sudo systemctl daemon-reload and sudo systemctl restart mediamtx-audio.
  3. Keep lyrebird-common.sh in the same directory as lyrebird-stream-manager.sh and install_mediamtx.sh, and run install from a checkout: the manager cannot write a MediaMTX configuration without the library, install_mediamtx.sh install needs it, and the unit is rendered from config/mediamtx-audio.service. A copy of one script alone in /usr/local/bin has none of that.
  4. Check the device configuration with sudo ./lyrebird-stream-manager.sh validate. Lines that were silently ignored before are now listed with their line numbers, and mixed-case keys now take effect.
  5. Replace mediamtx.yml where you want the new defaults (list above). The file the earlier manager wrote is replaced by the first start, after a backup. The file the earlier installer wrote is yours: until you replace it its API and metrics stay on every interface, SRT (and MoQ) stay on, and paths: {} still refuses every publisher.
  6. Move settings. A node that set MEDIAMTX_LOG_FILE and relied on the manager log being in the same file must also set STREAM_MANAGER_LOG_FILE. A node that uses MEDIAMTX_RTSP_PORT, MEDIAMTX_API_PORT, MEDIAMTX_METRICS_PORT, MEDIAMTX_API_BIND, MEDIAMTX_METRICS_BIND, RTSP_AUTH_MODE, RTSP_USERS_FILE, MEDIAMTX_HOST or MEDIAMTX_BINARY must run install again with them exported, for example sudo env RTSP_AUTH_MODE=local-only-publish ./lyrebird-stream-manager.sh install (with -m, -f and -n on a multiplex node): until then the unit and the cron file carry none of them, and a cron restart of MediaMTX renders the defaults. Lines you added by hand to /etc/cron.d/mediamtx-monitor for other settings are rewritten by every install, so add them again afterwards. Delete the removed settings (see Removed) from the unit; until then every run logs one warning.
  7. If the service was not restarted in step 2, restart it: sudo systemctl restart mediamtx-audio. On a node started by hand with the old code, the first stop or force-stop can wait STOP_LOCK_TIMEOUT seconds and refuse (exit 5), because MediaMTX and FFmpeg inherited the old lock; it lists the processes that hold it, and you stop them once.
  8. Check: sudo ./lyrebird-stream-manager.sh status ends with an overall state of ok, degraded or waiting_for_devices (status --json has the same), and systemctl status mediamtx-audio is active.

What changes without your doing anything:

  • A Prometheus on another machine that scrapes lyrebird-metrics.sh serve needs serve --bind ADDR (or 0.0.0.0) and a firewall. A cron job that redirects lyrebird-metrics.sh into a file should use --file PATH, which replaces the file atomically.
  • Alert state files of the previous version (<alert>.last) are no longer read, so the first identical alert after the upgrade can be delivered once more.
  • An /etc/lyrebird/storage.conf written from the old documentation, which was never read, now takes effect.
  • A script that reads the exit status of install_mediamtx.sh sees 11 where it saw 7 for an archive that did not extract, a missing binary or a failed copy into place.
  • Each monitor run opens a short RTSP read session per published stream. A MediaMTX that requires authentication to read refuses it (401): the failed probe is logged every run and never counted as silence. AUDIO_LEVEL_CHECK_ENABLED=false turns the check off.

  • Not run on hardware or under a real systemd manager. [LB-07, LB-11, LB-12, X-12, LB-23, LB-24, X-20, LB-15]
  • GitHub itself. The workflows were checked with actionlint and each step script was run locally; no run on GitHub is part of this check. Requiring the CI Summary check in branch protection, signing tags and attesting releases are repository settings this change does not make: a release carries a source tarball and SHA256SUMS, which prove integrity, not authorship. [LB-19, LB-20, X-22, X-16]
  • Older MediaMTX cannot validate a file. --validate-conf exists from 1.21.1; before that an unknown key or an invalid path name is found only when MediaMTX refuses to start (the reason is in /var/log/mediamtx.out). [LB-22]
  • install carries nine settings, no more. The path variables (MEDIAMTX_CONFIG_DIR, the PID, lock and log files, MEDIAMTX_FFMPEG_DIR) and the audio and policy settings are not written into the unit or the cron file, and the service is never given them. The unit's PIDFile=, StandardOutput=append: and ReadWritePaths= are rendered from the path variables of the shell that ran install, so a non-default MEDIAMTX_PID_FILE makes the unit name a PID file the manager does not write. Leave the paths at their defaults, or set them for the service (systemctl edit mediamtx-audio) and the cron file by hand; install rewrites the cron file, so repeat the lines after each run.   • RTSP has no authentication unless you configure it, and the metrics server none at all (one connection at a time; for several scrapers use --file and node_exporter's textfile collector). [LB-06]
  • The silence check is a log line, with a threshold not validated on real microphones. -60 dB was checked against digital silence (-91 dB) and an FFmpeg test tone only; a dead capsule that idles above it is not detected. The probe reads anonymously, so it cannot see a stream behind read authentication. [LB-14]
  • Nothing monitors a node set up only by the Quick Setup Wizard. The monitor, and with it late-device recovery and the silence check, is the cron job lyrebird-stream-manager.sh install writes, and the wizard does not run it. [LB-07, LB-21]
  • Known smaller defects, not fixed: a second updater started in the instant of a self-update's exec could take its lock; non-root status prints a garbled Resources: line for MediaMTX; the failure counter of the network check is the fixed file /run/mediamtx-network-failures; a card whose usbid shows up before its PCM entries is skipped until the next monitor run.
  • Older entries below claim more than was tested. "Cross-platform" and platform-list entries (orchestrator 2.0.1, diagnostics 1.0.2, installer 2.0.1) were never backed by a run on macOS, BSD or ARM: the suite runs on Linux, Bash 5.2, and tests/fetch_mediamtx.sh fetches linux amd64 releases only.

Correction (2026-11): the file is no longer sourced at all; it is read as data, line by line [LB-08].
  • Non-numeric env knobs aborted the cron monitor: 37 numeric knobs in the stream manager (e.g. CRON_RESTART_MAX_PER_HOUR=unlimited) reached bash arithmetic and killed every cron pass with an "unbound variable" error. All are now coerced to sane defaults at load; valid overrides are preserved.
  • Broken-clock mass deletion: age-based recording retention is skipped while the system clock is pre-2025 (not yet NTP-synced), and any recording whose mtime predates that epoch is kept — preventing minutes-old data from being deleted as "56 years old" the moment the clock steps. Emergency size-based cleanup is deliberately exempt.

Added

  • Inode-exhaustion detection in storage monitoring: a recorder writing many small files exhausts inodes long before blocks; cmd_monitor now applies the warning/critical/emergency thresholds to df -Pi too. Filesystems without inode accounting are treated as no pressure.
  • In-band metrics staleness marker: every scrape emits lyrebird_scrape_timestamp_seconds so a .prom left behind by a dead exporter ("dead recorder looks alive") is detectable via a Prometheus age alert.

Fixed (Reliability Hardening pass, 2026-07)

Deeper follow-up audit (6 parallel reviewers, every finding reproduced) closing the pending HIGH items and a large MEDIUM/LOW sweep. Every fix ships with a regression test; the suite is green (528 tests) and ShellCheck-clean.

  • Storage / data-loss: df output was misparsed on wrapped long device names (LVM//dev/mapper), so a FULL disk read as "OK" and cleanup never ran; empty-dir cleanup could delete the recording directory itself; oversized-log truncation swapped the inode out from under the writer (invisible unbounded growth); a non-integer retention env value aborted the script at load (crons silently stopped). Now POSIX df -P with guards, -mindepth 1, in-place truncation, and validated numeric inputs.
  • Metrics: the Prometheus scrape silently aborted in the normal "streams up, no listeners" state (unguarded curl/grep|wc under set -euo pipefail), so --file mode served a STALE .prom with up=1 — a dead recorder looked alive for months. Guarded all collectors; label values are now escaped.
  • Stream supervision: the wrapper gave up after a LIFETIME (not windowed) restart count, so streams died off one by one over weeks; a dead stream was never resurrected under cron (now bounded per-stream resurrection); disk/memory pressure triggered a 5-minute service-restart storm that freed nothing (now degraded/alert-only). Generated logrotate now uses copytruncate.
  • Installer/updater: a failed update left MediaMTX stopped indefinitely (rollback never restarted it); update -V <ver> ignored the pin and jumped to latest; a branch switch never fast-forwarded (no-op "success"); a self-update re-exec could strand the service on a prompt.
  • Alerts: every CRITICAL Pushover alert was rejected (missing retry/expire); ntfy titles containing a colon were truncated. Diagnostics: a healthy-host run could abort mid-way; several checks read false "healthy" (inotify, disk, world-writable config perms, "recent crash", BusyBox reachability).
  • USB mapper: closed a udev-rule injection via -u; made VID:PID-only naming visible; atomic rules-file write. mic-check: --format=json always emitted an empty list; config could pick an unsupported channel count.
  • Sample configs: removed systemd WatchdogSec restart-loop traps (MediaMTX can't feed it; the manager's ping is rejected under default NotifyAccess), fixed the audio unit's Type (forking) and StartLimit placement, and made logrotate use copytruncate. Added config-file validation tests.
  • Tests/CI: added a hardware-free end-to-end integration suite (stub MediaMTX API, mock webhook, disk-full, device-config round-trip); bumped ShellCheck 0.10→0.11 (verified clean), shfmt 3.8→3.13.1, actions/checkout v4→v5.
