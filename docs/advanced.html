Recovery Procedures

Stream Not Starting

# See which stream is not publishing and why
./lyrebird-stream-manager.sh status

# Restart everything (interrupts running streams)
sudo ./lyrebird-stream-manager.sh restart

# If that fails: kill what the manager started, then start fresh
sudo ./lyrebird-stream-manager.sh force-stop
sudo ./lyrebird-stream-manager.sh start

Do not delete files under /run to get past a refusal. A refused command names its reason: exit 5 means another lifecycle command holds the lock (the message names it), exit 8 means another MediaMTX owns the node. See Troubleshooting.

Device Not Found After Reboot

# Show USB sound cards, their ports and mappings
./usb-audio-mapper.sh --list

# Re-map a card that lost its name (applied and verified immediately)
sudo ./usb-audio-mapper.sh -n --card N -f NAME

# Verify the names and symlinks
cat /proc/asound/cards
ls -la /dev/sound/by-id/

Complete System Recovery

Use this procedure when the system is in an unknown or corrupted state:

# 1. Stop everything the manager started
sudo systemctl stop mediamtx-audio 2>/dev/null || true
sudo ./lyrebird-stream-manager.sh force-stop

# 2. Anything left that belongs to this suite? This only lists; read it before adding --yes
sudo ./lyrebird-stream-manager.sh force-stop --kill-all

# 3. Verify the MediaMTX installation
sudo ./install_mediamtx.sh status
# If the binary is damaged: sudo ./install_mediamtx.sh update

# 4. Verify device mapping
sudo ./usb-audio-mapper.sh --test

# 5. Check the device configuration, then run full diagnostics
./lyrebird-stream-manager.sh validate
sudo ./lyrebird-diagnostics.sh full

# 6. Fresh start
sudo ./lyrebird-stream-manager.sh start

force-stop removes the manager's PID files, wrapper scripts and markers itself. Leave the lock files (/run/mediamtx-audio.lock, /etc/mediamtx/.config.lock) alone: the kernel releases a lock when its holder exits, so there is no stale lock to clear, and removing a lock file that is held gives the next process a different lock.

Emergency Field Recovery (No Internet)

If in the field without internet access:

  • Per-device configuration backups: lyrebird-mic-check.sh saves /etc/mediamtx/audio-devices.conf.backup.<YYYYmmdd_HHMMSS> before it overwrites the file. sudo ./lyrebird-mic-check.sh --list-backups lists them and sudo ./lyrebird-mic-check.sh --restore restores one. No script creates an audio-devices.conf.bak.
  • MediaMTX configuration backups: when the stream manager replaces a generated mediamtx.yml it keeps the old one as mediamtx.yml.<UTC stamp>.<nn>.bak (the newest 5); the installer saves mediamtx.yml.backup.<YYYYmmdd-HHMMSS>. Copy one back over /etc/mediamtx/mediamtx.yml and restart.
  • Software versions: ./lyrebird-updater.sh --history and ./lyrebird-updater.sh --rollback [VERSION] need no network when the version is already in the clone.
  • Keep your own copy of a known-good configuration on a USB drive (see Backup & Restore).
  • Restart: sudo systemctl restart mediamtx-audio

Version Management

Branches and Tags

Branch/TagWhat it isUse
Release tags (git tag) Fixed points in the history Pin a production node to one only after checking that it contains the changes you rely on: git tag --contains <commit>
main The default branch; where changes land The current code. The updater's option 2 switches to the default branch
⚠️
The newest tag predates the fixes

The newest tag at the time of writing, v1.3.0, was made before the changes these pages describe, and the updater's option 1 ("latest stable release") is the newest tag. Until a newer tag exists, use main (option 2, or git checkout main). git tag --contains origin/main prints nothing while no release contains the current code.

Check for Updates

# Interactive menu
./lyrebird-updater.sh

# Command-line status
./lyrebird-updater.sh --status

# Fetch and list available versions/tags (needs the network)
./lyrebird-updater.sh --list

Upgrade to the Latest

# Via the updater (recommended: it stashes your changes, coordinates the service, and rolls back on failure)
./lyrebird-updater.sh
# Option 1: latest stable release (the newest tag)
# Option 2: the default branch (main)

# Or by hand (no service handling, no rollback)
git fetch --tags origin
git checkout main
git pull --ff-only
chmod +x *.sh

Switch to a Specific Version

# Via the updater
./lyrebird-updater.sh
# Select option 3: Switch to Specific Version or Branch
# Enter a tag, for example: vX.Y.Z

# Or by hand
git fetch --tags
git checkout vX.Y.Z
chmod +x *.sh

History and Rollback

# What was installed when, and any update that did not finish (local, no network)
./lyrebird-updater.sh --history

# Back to the version before the last completed update
./lyrebird-updater.sh --rollback

# To a release tag or a commit that is already in the clone
./lyrebird-updater.sh --rollback v1.3.0

A rollback is the update's own transaction run to a version already in the clone: your changes are stashed and restored, the service is stopped and started again, and nothing is fetched. A branch name is refused (exit 1) and a version that is not in the clone exits 6. Rolling back to a release older than updater 1.7.0 replaces the updater with that release's own, which has neither --history nor --rollback. The state (history, journal, lock) lives in .git/lyrebird-updater/; nothing needs to be deleted there.

Post-Update Migrations

The updater automatically runs migrations for breaking changes (for example script renames), including after an update that restarts the updater itself. To run them manually:

sudo ./lyrebird-updater.sh --migrate

Migration markers are kept in /var/lib/lyrebird/migrations/. Migrations are idempotent, so running them again is safe.

ℹ️
Script Rename Migration (release v1.3.0)

mediamtx-stream-manager.sh was renamed to lyrebird-stream-manager.sh. Running lyrebird-updater.sh updates systemd service files, cron jobs, and log paths. The orchestrator warns at startup if old names are detected.

API Integration

MediaMTX's control API listens on 127.0.0.1:9997 by default (MEDIAMTX_API_PORT, MEDIAMTX_API_BIND), and the default MediaMTX policy refuses callers that are not this machine. It is for reading state from the node itself: 

# List the paths MediaMTX knows
curl -s http://127.0.0.1:9997/v3/paths/list | python3 -m json.tool

# Details for one stream ("available" says whether it is publishing)
curl -s http://127.0.0.1:9997/v3/paths/get/mic-left

# Global configuration
curl -s http://127.0.0.1:9997/v3/config/global/get

For a decision in a script, prefer the stream manager's own report: ./lyrebird-stream-manager.sh status --json | jq -e '.overall == "ok"'. An example that sends a webhook when that fails is on Monitoring.

Prometheus Integration

# Start the metrics server (127.0.0.1:9100; add --bind for another host's Prometheus)
./lyrebird-metrics.sh serve --port 9100 &

# Configure Prometheus to scrape
# prometheus.yml:
# scrape_configs:
#   - job_name: 'lyrebird'
#     static_configs:
#       - targets: ['your-host:9100']

For anything beyond one poller on loopback, use --file and node_exporter's textfile collector; see Monitoring.

Backup & Restore

⚠️
Protect the archive

/etc/mediamtx/ can contain rtsp-users.conf and, with RTSP authentication, password hashes in mediamtx.yml. Keep the archive mode 600 and off shared media.

Create Backup

# Backup all configuration
sudo tar -czf lyrebird-backup-$(date +%Y%m%d).tar.gz \
  /etc/mediamtx/ \
  /etc/udev/rules.d/99-usb-soundcards.rules \
  /etc/systemd/system/mediamtx-audio.service \
  /etc/cron.d/mediamtx-monitor \
  /etc/lyrebird/ 2>/dev/null
sudo chmod 600 lyrebird-backup-$(date +%Y%m%d).tar.gz

echo "Backup created: lyrebird-backup-$(date +%Y%m%d).tar.gz"

Restore from Backup

# Restore configuration
sudo tar -xzf lyrebird-backup-20261101.tar.gz -C /

# Reload udev rules
sudo udevadm control --reload-rules
sudo udevadm trigger

# Reload systemd
sudo systemctl daemon-reload

# Restart the stream manager's service
sudo systemctl restart mediamtx-audio

Configuration-Only Backup

# Just the audio device configuration
sudo cp /etc/mediamtx/audio-devices.conf \
  /etc/mediamtx/audio-devices.conf.backup.$(date +%Y%m%d)

# Restore
sudo cp /etc/mediamtx/audio-devices.conf.backup.20261101 \
  /etc/mediamtx/audio-devices.conf

lyrebird-mic-check.sh -g makes such a backup by itself; see Emergency Field Recovery.

Debug Mode

Debug output is per script:

# Stream manager
sudo ./lyrebird-stream-manager.sh -d start

# USB mapper debug
sudo ./usb-audio-mapper.sh -D

# MediaMTX installer verbose
sudo ./install_mediamtx.sh --verbose install

# Diagnostics debug
sudo ./lyrebird-diagnostics.sh debug

# Storage script debug
sudo ./lyrebird-storage.sh --debug status

export DEBUG=1 does not enable debug output: the scripts that read DEBUG compare it with the word true, and in the stream manager DEBUG=true also turns on shell tracing (set -x), which is very verbose. Use -d.

Complete Uninstallation

To fully remove LyreBirdAudio and all components:

# 1. Stop all streams and services
sudo ./lyrebird-stream-manager.sh stop
sudo systemctl stop mediamtx-audio 2>/dev/null
sudo systemctl disable mediamtx-audio 2>/dev/null
sudo systemctl stop mediamtx 2>/dev/null
sudo systemctl disable mediamtx 2>/dev/null

# 2. Uninstall MediaMTX
sudo ./install_mediamtx.sh uninstall

# 3. Remove systemd units, the cron job and the logrotate file
sudo rm -f /etc/systemd/system/mediamtx-audio.service
sudo rm -f /etc/systemd/system/mediamtx.service
sudo systemctl daemon-reload
sudo rm -f /etc/cron.d/mediamtx-monitor
sudo rm -f /etc/logrotate.d/mediamtx

# 4. Remove USB device rules
sudo rm -f /etc/udev/rules.d/99-usb-soundcards.rules
sudo udevadm control --reload-rules
sudo udevadm trigger

# 5. Remove configuration files
sudo rm -rf /etc/mediamtx/
sudo rm -rf /etc/lyrebird/

# 6. Remove state files
sudo rm -rf /var/lib/mediamtx-ffmpeg/
sudo rm -rf /var/lib/mediamtx/
sudo rm -rf /var/lib/lyrebird/

# 7. Remove log files
sudo rm -f /var/log/mediamtx.out
sudo rm -f /var/log/lyrebird-stream-manager.log
sudo rm -rf /var/log/lyrebird/

# 8. Remove the repository
cd ~
rm -rf /path/to/LyreBirdAudio

The files in /run (/run/mediamtx-audio.*, /run/lyrebird/) are on a tmpfs and disappear at the next reboot; leave them. If the stream manager's stop reports that it could not stop something, list what is left with sudo ./lyrebird-stream-manager.sh force-stop --kill-all (it prints, and signals nothing without --yes). Do not use pkill by name: it also kills other installations' processes.

Verify Complete Removal

# Check for remaining processes
ps aux | grep -E "mediamtx|ffmpeg" | grep -v grep

# Check for remaining services
systemctl list-units | grep -E "mediamtx|lyrebird"

# Check for remaining config
ls /etc/mediamtx/ 2>/dev/null || echo "✓ Config removed"
ls /etc/udev/rules.d/99-usb-soundcards.rules 2>/dev/null || echo "✓ udev rules removed"
ls /var/lib/mediamtx-ffmpeg/ 2>/dev/null || echo "✓ State removed"

Partial Cleanup (Keep MediaMTX)

# Remove only streaming state (keep MediaMTX installed)
sudo ./lyrebird-stream-manager.sh stop
sudo rm -rf /var/lib/mediamtx-ffmpeg/
sudo rm -f /var/log/lyrebird-stream-manager.log
